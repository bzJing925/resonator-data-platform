## 1. 目标和交付顺序

实现可独立运行的寻优程序，寻找 k²、Qs、Qp、Bode Q 分别最优的结构，并提供多目标 Pareto 候选。每个候选同时展示完整性能向量、结构参数、适用范围、数据来源和误差依据。

分两次验收：

- **M1：已有数据支持下的寻优工具。** 完成可靠结构标签、实测排名、经过结构留出验证的代理、约束搜索、结果导出和独立结果页面。

已有外推路线直接引用 [有限外推实施计划](/Users/jingbozuo/00.PROJECTS/ALN-DATA/aln-data-master/docs/superpowers/plans/2026-10-12-baw-sim-to-real-extrapolation-plan.md)，本计划补充执行顺序、阶段验收和人员分工。

### P0—P1：先确定数据含义

统一记录来源文件和行号、原始描述、mark、端口、结构类型、尺寸及单位、几何 has_pf、去嵌状态、物理器件标识和质量标记。空缺与真实零值分别表达，保留原描述供复核。

只丢弃真正未命中 ELB002 的 DUT，校准件保留为重新去嵌的输入。既往精确匹配发现两份结果表均有对应编号，因此不能照旧解析器的漏配计数直接删除。

共享解析规则应在理解全部调用方后修复，并检查常规编号、K-10、表头、空格 token、缺失值、S11/S22 面积和特殊拓扑。对 BASIC、Airgap 等语义，先利用设计材料判断；证据不足的分支不进入首版可信模型。

**G1：结构标签与覆盖矩阵可用后，才能启动正式训练。** 未解决的特殊分支可隔离，可靠子集不必等待全部特殊结构处理完毕。

### P2—P3：先知道实测表现，再决定模型

使用有效样本的完整重复分布，而不是只用旧训练集每格挑选的 5 条代表样本。结构典型值、组内波动及估计不确定性分别报告；检查位置相关性对区间的影响。

主 agent 与验证子 agent 共同冻结结构分组、外层测试、边界留出和评价方法。相同有效结构不因 mark 不同而跨组，相关器件/端口和 raw/de 版本按验证目的隔离。标签驱动的清洗、归一化、基准表及校准器只在相应训练折内建立。

先比较邻近实测、ExtraTrees、分层 GP 等低复杂度候选，现有模型作为有来源限制的对照。候选模型既比较预测误差，也比较 Top-K 推荐表现、边界误差和区间校准；不用训练误差选冠军。最终测试不参与超参数、模型选择或阈值修订。

重复性分析和使用需求用于确定误差阈值，并在最终测试/盲测前冻结。当前不预设任意准确率。若代理没有充分证据支持未测组合，M1 仍可交付实测结构排序，模型探索部分单独列明。

**G2：每个目标的误差和支持边界明确后，才开放对应的可信模型寻优。** 不为赶页面而把来源未知或未经评估的输出直接作为目标。

### P4—P5：计算、展示和导出使用同一结果

模型以批量接口返回指标、区间/不确定性类型、支持等级和版本。寻优器只处理合法结构、约束和排名；页面消费同一结果格式。指标缺失必须明确，不用 0 占位参与排名。

首版先完成可独立运行的本地 Python 寻优程序，页面可离线载入其结果，支持候选筛选、单目标切换、Pareto 对比和导出。新的任意计算范围由程序重算，不把已有候选筛选冒充实时预测。

如果要求把实时寻优完整放进单个 HTML，应在 P3 同时确认模型的浏览器推理/导出方案，完成跨端数值和支持边界一致性检查后交付。不能假定所有 Python 模型都可直接复用现有 ONNX 推理链。现有代理模型 HTML 继续保留，曲线标注对应模型版本；仅有幅值曲线时不声称从中重提了相位相关 Q。

控制候选数量、分批预测并复用已加载模型。搜索只调用所需标量预测，完整谱仅为少量候选生成；记录搜索规模、实际耗时与内存，再决定是否需要进一步优化。

**G3：P1—P5 的数据、模型、功能及真实交互验收通过，才标记 M1 完成。**

### P6：把新区域探索做成可验证实验

先选同材料、同工艺、同拓扑下一个连续尺寸方向。仿真需要包含并校准与目标 Q 相关的损耗信息，已有仅提供 fs/fp/k² 的补点不能证明 Q 外推。

先按整段边界留出做回溯验证，再在仿真支持范围内预先确定原实测没有的新结构。冻结预测、测量方案和成功标准后开展盲测。详细物理路线与失败处置沿用已有有限外推计划。

**G4：只有新的独立实测达到预先标准，才标记 M2 完成。** 缺少 COMSOL 模型、计算资源或新器件测量时，交付具体资源需求和补点清单，状态保持“外推未验证”。

## 4. 是否需要子 agent

**完整 M1 实施建议使用主 agent + 2 个子 agent。** 本次按用户后续指令，由主 agent 自主完成基础 P0—P3，并以单独核验脚本检查真实产物；未启动子 agent。复杂算法由 astra 后续接手。以下保留完整实施的建议分工。

任务存在可以分离的工作面：数据处理、模型/寻优、独立验证。子 agent 能并行核对现有训练链和实现数据处理，并使验收不完全依赖模型作者自查。结构含义、冲突裁决、统一指标和最终集成仍由主 agent 负责。

| 角色 | 责任 | 输入与交付 | 边界 |
| --- | --- | --- | --- |
| 主 agent | 目标与数据契约、模型选择/训练、寻优核心、阶段判断和集成 | 冻结规格、模型包、搜索程序与完整验收结论 | 统一裁决有证据的标签规则；不替代缺失的物理设计证据 |
| 子 agent A：数据与交付界面 | P1 数据整理及 P2 实测统计；完成后转 P5 独立结果页面 | 来源清单、规范数据、冲突报告、覆盖表；随后页面与导出交互 | 只编辑分配的模块；不修改模型训练和寻优核心；不自行猜面积/拓扑标签 |
| 子 agent B：验证与审查 | 初期只读检查旧训练来源、划分和指标；随后实现独立评价并检查最终推荐 | 验证规格、结构/边界留出检查、误差和排名报告、功能审查 | 不改训练目标以迎合结果；不参与核心模型实现；失败与未覆盖范围必须如实报告 |

### 调度顺序

1. P0 由主 agent 完成目标、数据格式和写入范围。完成后才派发实现任务。
2. P1 时 A 做数据整理，B 并行只读审查旧模型及验证设计；主 agent 追溯标签冲突和整合规则。
3. 数据与划分冻结后，主 agent 开展 P3 模型实验；A 完成实测基线并准备页面，B 建立独立评价流程。
4. 模型与结果接口稳定后，主 agent 开发 P4，A 开发页面；B 对冻结版本做误差及边界评估。
5. 收尾时 B 检查数据泄漏、目标一致性、支持范围和结果导出，主 agent 完成端到端验收。P6 依照物理资源到位情况继续。

并行不等于同时进行全部训练。单机资源密集的训练和仿真需要排队，避免内存、GPU 或输出目录相互影响。数据语义、模型选择和验收结论也不通过多数表决决定。

### 协作约束

- 主 agent 维护一个数据契约、一个冻结 split manifest 和一个结果格式。子 agent 需要变更时先报告影响，再由主 agent 更新。
- 每个子任务指定输入版本、可编辑目录、交付格式和检查方法。共享配置、锁文件、同一个解析函数不分给两人同时修改。
- ML/训练改动放在 `/Users/jingbozuo/Projects/aln-data-backend-ml`；集成文档和现有 HTML 入口在当前 main 工作区。跨工作区的依赖与集成由主 agent 统一处理。
- ML 工作区已有训练脚本改动和多套产物。开始时记录现状，新增实验使用独立目录，不 reset、不清理、不覆盖原产物。
- 验证子 agent 用冻结数据和配置报告结果，开发中使用过的测试数据不能再次宣称独立盲测。

## 5. 资源依赖与最终检查

M1 依赖现有两份结果表、ELB002、项目本地 uv 环境，以及特殊结构/面积冲突的设计依据。若部分依据缺失，先限定到标签明确的子集。复数曲线核查可能需要从约 9.8 GiB 原始 zip 按需恢复文件，先抽样核对再决定全量处理。

M2 额外依赖可复用的 COMSOL 模型、必要损耗参数、计算资源、器件制造/测量条件与一致的去嵌流程。增加子 agent 数量不能替代这些资源。

最终检查覆盖四个层面：

1. 数据：来源与排除原因可追溯，结构语义、单位和端口一致。
2. 预测：分组与边界验证成立，区间含义正确，旧模型和新模型口径清楚。
3. 寻优：单目标与 Pareto 逻辑可核验，非法/无支持输入可拒绝，无可行解不会静默放宽条件。
4. 交付：程序、页面、导出、模型和数据版本一致；M1/M2 完成状态分别说明。

P0—P3 已交付数据修订规则、覆盖矩阵、实测排名、基础代理、冻结划分及边界评估。后续由 astra 先审查 P3 暴露的边界误差与区间失效，再决定复杂模型和 P4 的可信范围；不将本次阶段完成等同于 M1/M2 完成。

# 工艺参数数据域设计规格

日期：2026-07-20
状态：已评审（头脑风暴阶段确认）

## 1. 背景与目标

客户提供的工艺参数表格 `副本SICM_AlN_DT.xlsx` 记录了 AlN BAW 谐振器制造的关键工序数据：ICP 刻蚀、Mo 底电极生长、AlN/AlScN 压电层生长。每行对应一次工艺运行（一片晶圆或一个实验），包含工艺条件（气体流量、功率、时间）与表征参数（厚度、均匀性、应力、电阻率、粗糙度、XRD 半高宽等）。

目标：将该表格数据纳入数据管理平台——入库、提供浏览/筛选/导出的 Web 页面。

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 与测试数据的关联 | **暂不关联**：工艺表晶圆号（F0425LW1、0623A07 等）与平台批次号（T8901P.01 等）无程序可判定的对应关系，工艺数据作为独立数据域管理 |
| 更新方式 | **一次性导入**：离线脚本导入，不做上传功能与解析流水线 |
| 存储方案 | **方案 A：三个类型化表**（每工序一张表），类型化列 + 单位后缀命名，与 `devices` 表约定一致 |
| 前端形态 | 新页面 `/process`：按工序分 tab，表格浏览 + 客户端筛选/排序 + CSV 导出 |
| 服务端导出 | 不做：总量约 300 行，前端内存数据直接生成 CSV（所见即所得） |

## 3. Excel 源数据勘察结论（已核实）

工作簿共 4 个 sheet：

| Sheet | 工序 | 数据行数（约） | 特殊结构 |
|---|---|---|---|
| `SPM2 ICP Etch` | ICP 刻蚀 | 62 | **3 个重复表头块**（行 3/33/61 起）；块间有 `mean` 汇总行与 `spec. <5%` 行；块无标题文本 |
| `SPM3 Mo` | Mo 生长 | 71 | A 列为实验组标签（DOE5、TEST6、IAT、XRD 等，可空）；存在 `??` 脏单元格 |
| `SPM4 AlScN(30AT)` | AlScN 生长 | 116 | A 列为实验组标签（S21、A14、DOE6 等，可空）；部分 `run_no` 为实验名（DOE1、Tilt-0）而非晶圆号 |
| `AlSc` | AlSc 生长 | 49 | 多一个 `Recipe ID` 列；第 5 行为规格目标行（`3500 / <0.5% / <300`，run_no 为空）；中间有空白行 |

已核实的格式细节：

- 表头为两层结构（`Information`/`Measrements` 分组行 + 字段名行 + 单位行），解析按显式列配置定位，不做通用表头识别
- `WiW 1sig/%`、`WtW 1sig/%` 等列单元格为百分比格式（`0.00%`）：存储值 0.029 即显示 2.9%，导入时 ×100
- `WtW 1sig/%` 等组级统计列存在**跨行合并单元格**（如 G15:G24，10 片晶圆共用一个 WtW 值）
- ICP sheet 厚度单位为埃（`THK/A`），其余 sheet 为纳米（`THK/nm`）
- 部分 `Dep. Time` 为小数（如 307.268…），所有数值列统一用 float

## 4. 数据模型

## 5. 解析规则

解析器为纯函数模块 `backend/app/core/process_params.py`：输入 xlsx 路径，输出三张表的行数据（dataclass 列表）+ 解析报告（每 sheet 导入行数、跳过行数、清洗单元格计数）。不写文件、不碰数据库。

- **显式列配置**：4 个 sheet 各一份硬编码配置（列字母 → 字段名），不做"智能"表头识别
- **数据行识别**：`run_no`（No. 列）非空 → 数据行；为空 → 跳过。此规则自动排除：表头行（No. 列值为 `'No.'`/`'Information'` 的行需额外按字面排除）、`mean` 汇总行、`spec.` 行、AlSc 规格目标行、空白行
- **脏单元格**：数值列中 `??` 等无法转 float 的值 → NULL，计入解析报告（单元格地址 + 原值）
- **百分比列**：单元格 `number_format` 含 `%` → 值 ×100 存 `_pct` 列
- **合并单元格**：openpyxl 默认只返回锚点值，其余行为 None——保持原样，**不向下填充**（WtW 为组级统计，填充会误导为单晶圆数据）
- **ICP 表头块**：每遇到一个新的表头行（No. 列值 = `'No.'`）`block_index` 递增
- **跳过行的上下文**：ICP 块间的 `mean`/`spec.` 行不导入（属于块级统计，与合并单元格同理不归属单行）

## 6. 导入脚本

`backend/scripts/import_process_excel.py`，离线运行：

```bash
cd backend
uv run python scripts/import_process_excel.py "../副本SICM_AlN_DT.xlsx" [--replace]
```

- 调用 `parse_process_workbook` 解析 → SQLAlchemy 批量插入三表
- 目标表非空时默认报错退出并提示；`--replace` 先清空三表再导入（保证可重复执行）
- 结束打印每 sheet 摘要：导入 N 行 / 跳过 M 行 / 清洗 K 个脏单元格（附明细）

## 7. API

新路由模块 `backend/app/api/process.py`（注册进 `app/main.py`），prefix `/api/process`：

| 端点 | 说明 |
|---|---|
| `GET /api/process/steps` | `[{key, label, row_count}]`：`icp_etch`（ICP 刻蚀）、`mo_dep`（Mo 生长）、`aln_dep`（AlN 生长） |
| `GET /api/process/{step}` | `{fields: [{name, label, unit, kind}], rows: [...]}` 全量返回；未知 step → 404 `{"detail": "未知工序: xxx"}` |

- 字段元数据（中文 label、unit、kind ∈ `numeric`/`text`）以后端常量定义，与表结构同源
- 无分页、无筛选参数（全量最多约 300 行）；无服务端导出端点

## 8. 前端

- 新页面 `frontend/src/pages/Process.tsx`，路由 `/process`，导航增加"工艺数据"
- 三个工序 tab，切换时请求 `GET /api/process/{step}`
- 表格：原生 `<table>`，风格与 BatchDetail 一致；表头显示中文 label + 单位；点击表头切换升/降序
- 筛选区：按字段元数据生成——`numeric` 列 min/max 两个输入，`text` 列包含匹配输入；全部客户端完成
- "导出 CSV"按钮：将当前筛选 + 排序后的行序列化为 CSV（UTF-8 BOM，Excel 可直接打开），Blob 下载，文件名如 `process_mo_dep.csv`
- 加载/错误状态处理与现有页面一致

## 9. 错误处理

| 场景 | 行为 |
|---|---|
| 导入：文件不存在 / 非 xlsx | 明确报错退出（非零 exit code） |
| 导入：sheet 缺失 | 报错列出缺失 sheet，退出（4 个 sheet 应全部存在） |
| 导入：脏单元格 | 置 NULL，计入报告，不中断 |
| 导入：目标表非空且未加 `--replace` | 报错退出并提示 `--replace` |
| API：未知 step | 404 `{"detail": "未知工序: xxx"}` |
| 前端：接口失败 | 页面显示错误信息（与现有页面一致） |
